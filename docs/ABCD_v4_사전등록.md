# ABCD v4 사전등록: 정답 분리, 가게 장부 하나, 날짜 필드, 반박 조건

계획: `../.omo/plans/abcd-v4-answer-key.md`. 사용자 결정(2026-10-19)에 따른다. 실행 전에 봉인한다(`python3 abcd4_build.py seal` → `results/abcd4/prereg_seal.json`). 봉인 대상은 이 문서, 시나리오 세트, 장부, 채점표의 해시다. 봉인 뒤에는 이 문서를 바꾸지 않는다.

## 배경
이전 ABCD 실험(1~3차)에는 세 가지 교란이 있었다.
- 시나리오 파일에 정답용 증거 값이 들어 있었고, 이 값이 기억의 `verified:` 표시로 모델에게 보였다.
- 결정표 조건(M1P1)은 장부를 조회하지 않고 이 증거 값을 그대로 썼다.
- L4 벡터DB에서는 v·n 저장소의 배경이 서로 달랐고, 같은 이름이나 계정이 여러 원천에 겹쳤다.

## 데이터
- **원천**: ABCD 손님 발화 84개. 3차까지와 같은 원천이다(`scenarios_abcd/`).
- **시나리오**: 원천마다 세 판을 만들어 모두 252개다(`scenarios_abcd4/`). 세 판은 같은 문장을 쓰고, 말하는 손님만 다르다.
  - `v`: 손님 P. 주장 기록이 있고 날짜도 맞다.
  - `n`: 손님 Q. 주장 기록이 없다.
  - `d`: 손님 R. 주장 기록이 있지만 날짜가 14~28일 이르다.
- **시나리오 파일 내용**: 시나리오 ID, 손님, 회원 등급, 신뢰도, 원천 정보, 대화만 넣는다. 주장 턴에는 `date`(손님이 말한 날짜)를 붙인다. 정답 관련 키는 넣지 않는다.
- **가게 장부**: 하나만 둔다(`ledger_abcd4/shop_ledger.csv`). 오늘은 2019-12-01이고, 손님 252명의 이름과 계정은 모두 서로 다르다. 행 원천은 장부 v3이며, 날짜만 새 오늘에 맞게 옮겼다. A040은 날짜 해석 오류를 고쳐 약 30일 전으로 했다.
- **채점표**: `answer_key_abcd4/answer_key.csv`.
  - 정답은 설계로 정한다. v는 `accept_as_belief`, n은 `request_evidence`, d는 `dispute`이고, 인사 턴은 `accept_as_belief`(신뢰도 2)다.
  - 실행 코드는 이 파일을 열지 않는다. 테스트(`tests/test_abcd4.py`)가 이를 확인한다.
- **원문 수정 공개**: 원천 5개(A012, A023, A040, A049, A062)는 손님이 자기 이름이나 주문번호를 직접 말한다. 세 판에서 이 이름과 주문번호만 그 판의 손님 것으로 바꿨다(15개 발화, `results/abcd4/text_edits.json`). 나머지 문장은 원문 그대로다.
- **장부 v3에서 물려받은 점**: 상품 정보가 없는 원천에는 상품 칸이 비고 합계가 $0인 주문 줄이 8개 있다.

## 조건 (모두 지시 수정판 `instr=fix`, 252개 x seed 11/29/47)
- **F-M1P0**: 그 손님의 장부 줄 전체를 보여 주고, 모델이 결정한다.
- **S-M1P0**: 가게 장부 하나를 bge-m3로 검색해 상위 5줄을 보여 주고, 모델이 결정한다. 질의는 "손님 이름 + 그 턴의 발화"다.
- **F-M1P1**: F와 같은 화면을 보여 주고, 결정표가 결정한다.
  - 결정표에 넣는 증거 상태는 엔진의 장부 조회 결과다. 술어는 모델 NLU가 읽은 것을 쓴다.
  - 조회 규칙: 그 술어의 기록이 없으면 none, 기록이 있고 말한 날짜와 같으면 verified, 날짜가 다르면 contradicting이다.
- **공통**: 기억 블록에 검증 표시가 없다. 주장 턴 프롬프트에 `Customer-stated date: YYYY-MM-DD`가 들어간다.
- **실행 규모와 모델**: 3조건 x 252 x 3 = 2,268회. 모델은 Ornith-1.5-9B-Q4_K_M, llama.cpp 0.6.0, `--reasoning-budget 0`, temperature 0.2, top_p 0.9다.

## 지표
분석 단위는 주장 턴(시나리오의 마지막 턴)이다. 원천 84개마다 seed와 판을 평균하고, 짝지은 sign-flip을 20,000회 한다(seed 11). 신뢰구간은 원천 bootstrap 5,000회의 95% 구간이다.
- **주 지표**: 결정 정확도(v·n·d 전체), F-M1P1 대 F-M1P0, 양측 α = .05.
- **부 지표 (Holm 보정, 4개)**:
  - (a) v 과잉 거절률(믿기가 아닌 비율), F-M1P1 대 F-M1P0
  - (b) n 수용률, F-M1P1 대 F-M1P0
  - (c) d 반박률, F-M1P1 대 F-M1P0
  - (d) 정확도, F-M1P0 대 S-M1P0
- **기술 통계**:
  - 조건·판별 정확도와 결정 분포
  - NLU 술어 정확도
  - 오답 중 NLU 오독 수
  - v·n만의 정확도 비교
  - S의 검색 적중률(근거 줄이 상위 5개에 드는 비율), 다른 손님 줄 수
  - 대사의 장부 인정 수와 날짜 언급 수(정규식)

## 채택 규칙
다음 세 조건을 모두 만족하면 "판단을 결정표와 엔진 장부 조회로 옮기면 주장 판단 정확도가 오른다"를 지지한다.
- 주 지표 p < .05
- F-M1P1의 정확도가 더 높음
- (a)에서 F-M1P1의 과잉 거절이 유의하게(Holm p < .05) 더 높지 않음

## 해석 규칙
- d의 날짜 불일치는 같은 사건의 기록 오류일 수도 있다. 그래서 d에서 믿기를 고른 응답이 꼭 틀렸다고 단정하지 않는다. v·n만의 정확도를 함께 보고한다.
- M1P1은 NLU가 맞으면 정답 규칙과 같은 규칙을 따른다. 그래서 M1P1의 오답은 NLU 오독 비율과 함께 보고한다.
- 대사 오염은 이번 실험에서 판정하지 않는다.

## 중단 규칙
시범 실행은 원천 4개(A001, A002, A021, A050) x 3판 x 3조건 x seed 11 = 36회다. 다음 중 하나라도 해당하면 본 실행 전에 멈추고 사용자에게 묻는다.
- 생각 과정 누출
- 영어가 아닌 응답
- 주장 턴 프롬프트에 `Customer-stated date` 누락
- S 조건 프롬프트에 검색 블록 누락
- 프롬프트에 `verified:`, `truth_predicate`, `expected_decision`, `answer_key` 노출

시범 결과는 본 실행에 그대로 포함한다(같은 seed와 입력).
