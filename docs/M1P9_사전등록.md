# 라이브 M1P9 사전등록 (고친 기준②로 템플릿 출력 재검증, 새 시나리오 24편)

작성: 2026-10-17. 이 문서, `nlu_m1p9_live.py`, `logs/m1p9/precheck.json`, 의존 파일(`npc/speech.py`, `npc/eval.py` 포함)은 새 시나리오 폴더 `scenarios_m1p9/`가 생기기 **전에** 봉인한다(`logs/m1p9/prompt_freeze.json`).

## 1. 배경

M1P8에서 템플릿 출력(C)의 기준② 12건은 모두 S73의 엔진 문장 "자네, 그 말씀을 뒷받침할 증거를 보여주겠어요?"였다. 이 문장의 "보여**주겠**어요"가 금지 패턴 `(드리겠|주겠|줌세|주마)`에 걸렸다. 손님에게 증거를 요청하는 말이 NPC의 약속으로 잘못 채점된 것이다. 이 해석은 결과를 본 뒤에 했으므로 M1P8의 판정은 바꾸지 않았다. 이번에는 채점 규칙을 고정한 뒤 새 시나리오로 다시 검증한다.

## 2. 고친 기준②

- 금지 정규식을 적용하기 **전에**, 손님에게 하는 요청 동사 `(보여|알려|말해|말씀해)\s?주(겠|세|시)`를 "□"로 가린다.
- 두 조건에 똑같이 적용한다.
- 원래 채점(가리기 없음)도 함께 기록한다.

## 3. 사전 점검 (`logs/m1p9/precheck.json`, 봉인 대상)

M1P8 기록을 다시 채점한 결과다.

| 조건 | 원래 채점 | 고친 채점 |
|---|---:|---:|
| M1P7 | 33 | 27 |
| M1P8E | 31 | 28 |
| M1P8 | 12 | 0 |

- 가려서 빠진 문장 8종은 모두 손님에게 무언가를 요청하는 말이었다(직접 확인). 주장을 단정한 문장은 0건이다.
- 이 결과는 설계 근거이며 확인적 결과가 아니다.

## 4. 조건 (귀와 정책은 같다)

| 조건 | 귀 | 출력(runner 조건) |
|---|---|---|
| B = M1P8E | M1P8과 같은 kNN + 새 승계. 소문 규칙은 끈다 | `"M1P1"`(모델 대사) |
| C = M1P8 | B와 같다 | `"M1P3"`(엔진 템플릿, 모델 원문은 감사 기록) |

## 5. 새 시나리오

- 블라인드 작성 에이전트가 S80~S103(24편, 편마다 8턴)을 쓴다.
- 형식과 구성 규칙은 M1P8 브리프와 같다.
- 형식 검증만 하고 봉인한다.

## 6. 실행

24편 × seed 11/29/47 × 2조건 = 144런을 1회 실행한다. 중단되면 빠진 run_id만 이어서 실행한다.

## 7. 분석과 판정

- **주 검정**: 고친 기준②의 비율 C vs B. 시나리오 단위 부호뒤집기 순열검정(양측, α=0.05)을 하고, 부트스트랩 CI는 10,000회로 구한다.
- **부 검정(Holm, 3개)**: 결정 일치 C vs B, 기준① C vs B, 원래 채점 기준② C vs B.
- **기술 통계**: 턴 지연 중앙값과 p95.
- **템플릿 출력 채택**: 주 검정 p<0.05, C가 더 낮고, C의 결정 일치율 ≥ B의 결정 일치율.

## 8. 한계

1. 가리기 규칙은 M1P8 결과를 보고 만들었다. 평가는 그 뒤에 만든 새 시나리오로만 한다.
2. 금지 정규식은 시나리오 작성 에이전트가 쓰고 독립 검수는 받지 않는다(`draft_pending_user_approval`).
3. 정규식 채점이라 놓치는 경우나 다른 오탐이 있을 수 있다.
4. 템플릿 조건도 감사용 모델 원문을 생성하므로 지연 단축은 주장하지 않는다.
