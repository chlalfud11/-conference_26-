# NLU V3 검증 사전등록 (새 문장 세트)

작성: 2026-10-15. 이 문서와 `nlu_v3.py`는 새 문장 세트가 만들어지기 **전에** 봉인한다(`logs/nlu_heldout/prompt_freeze.json`).

## 1. 배경

M1P5 실험(`results/bottleneck/report.md`)에서 NLU 개선안 두 가지가 서로 다른 오류를 고쳤다. V1(출처 정의)은 소문 판별을 고쳤고, V2(직전 손님 발화 문맥)는 고위험 주장을 저위험으로 읽는 오독을 고쳤다. 대신 V2는 앞 말을 따라가는 편향을 새로 만들었다. 기존 27편은 이미 설계에 쓰였으므로 V3 검증에는 쓸 수 없다.

## 2. 개입

- **V3** = V1 정의 + 직전 손님 발화 최대 2개 + 문맥 사용 규칙("지금 말이 앞 주장을 가리키거나 되풀이할 때만 문맥을 보고, 새 화제면 지금 말만 본다") + 문맥 예시 3개(시나리오에 없는 물건 사용).
- 비교 대상: B(원본), V1, V2. 프롬프트 원문은 `nlu_v3.py`(V3)와 봉인된 `nlu_improve.py`(B, V1, V2)에 있다.
- 모델, seed(11, 29, 47), 스키마, 정책은 같다.

## 3. 새 문장 세트

- 작성자: 이 실험의 프롬프트, 결과, 기존 시나리오를 보지 않은 별도 작성 에이전트. 정의와 구성 규칙만 받는다.
- 구성: 대화 30개 × 손님 발화 4줄 = 120줄. 줄마다 정답 술어(`config.CLAIM_PREDICATES`)와 유형을 단다.
- 상태: `draft_pending_user_approval`(사용자 승인 전 초안).
- 작성 후 구성만 점검하고(라벨 유효성, 개수) 문장과 라벨은 고치지 않는다. 봉인 후 추론한다.

## 4. 지표·검정

- 단위: 줄 × seed 호출 1회. 위험도(고/저) 일치 여부. 위험도는 정책 입력이므로 결정과 1:1로 대응한다.
- **주 검정**: V3와 B의 위험도 정확도 차이. 대화 30개를 단위로 한 부호뒤집기 순열검정(양측, α=0.05)을 쓴다. 0이 아닌 차이가 20개 이하이면 정확 계산, 그보다 많으면 100,000회 표본(seed 20261015)이다. 부트스트랩 95% CI는 10,000회로 구한다.
- **부 검정 2개 (Holm)**: V3 vs V1, V3 vs V2(같은 방법).
- 기술 통계: 술어 정확도, 고→저, 저→고, 유형별 정확도, 스키마 성공률.
- 기술 평가(검정 없음): V3를 기존 27편 채점턴에 돌린 결정 일치율. 이 자료는 설계에 쓰였으므로 일반화 근거로 쓰지 않는다.

## 5. 채택 규칙

주 검정 p<0.05, 차이 > 0, V3의 고→저 건수 ≤ B의 고→저 건수를 모두 만족하면 V3를 "권장 NLU"로 보고한다. 아니면 채택하지 않는다.

## 6. 종료 규칙

정해진 호출을 1회만 실행한다. 결과를 보고 문장, 라벨, 프롬프트, seed를 바꾸거나 추가하지 않는다. 모든 검정은 null 결과까지 보고한다.

## 7. 미리 밝히는 한계

1. 새 세트 작성자도 같은 계열의 언어 모델 에이전트다. 사람이 쓴 자연 발화가 아니다.
2. 정답 라벨도 작성자가 붙였고, 독립 검수는 없다.
3. 줄 단위 NLU 평가이며 전체 대화 라이브 실행이 아니다. 정책이 결정적이라 위험도 정확도가 결정 정확도와 같지만, 대사 품질은 측정하지 않는다.
4. V3 설계자(실행자)는 V2 부작용 사례를 본 뒤 규칙을 썼다.
