# ABCD v5 사전등록: 놓친 주장을 다시 확인하는 2단계 결정표 (re-verify)

계획: `../.omo/plans/abcd-v5-reverify.md`. 사용자가 2026-10-20에 승인했고, "발동 실행만 새로 실행"으로 바꾸는 것도 승인했다.
실행 전에 봉인한다(`ABCD4_SET=heldout python3 abcd5_live.py seal` → `results/abcd5/prereg_seal.json`). 봉인 대상은 이 문서와 검증 세트의 시나리오·장부·채점표 해시다.

## 배경
- v4의 기존 결정표(F-M1P1)가 틀린 경우는 모두 NLU 오독이었다. 그중 '주장 없음'으로 읽은 경우가 v·n·d 각 41건이다.
- fail-closed는 이 41건을 모두 증거 요구로 바꾼다. 그래서 n은 개선되고, v는 같은 수만큼 나빠지고, d는 그대로다(1:1 교환). 실제 실행 233회가 오프라인 예측과 모두 일치했다.

## 조건: F-M1P1RV
F-M1P1과 같다. 다른 점은 첫 단계 NLU가 '주장 없음'을 냈는데 발화에 `TRANSACTION_CUE`가 있을 때뿐이다. 이때 다음 순서로 처리한다.
1. **후보 고르기**: `abcd4_runner.CUE_CANDIDATES`의 단서로 후보 술어를 정한다. 표 순서가 우선순위다.
   - promo / code / coupon / discount → promised_discount
   - return / refund → completed_errand
   - charge / bill / paid / pay → paid_deposit
   - order / deliver / shipp → reserved_item
   - bought / purchase / receipt → owns_item
2. **재질문**: 후보마다 `REVERIFY_INSTRUCTION`으로 참/거짓을 묻는다. 스키마는 `{"asserts": boolean}`이고 seed는 같다.
3. **결정**: 처음 참이 나온 술어로 장부를 조회하고, 그 결과로 기존 결정표가 결정한다.
4. **모두 거짓일 때**: 고위험으로 처리해 증거를 요구한다(fail-closed).

## 데이터
- **검증 세트 (확증)**: ABCD v1.1의 **dev와 test 분할**에서 뽑았다(`abcd5_heldout.py`).
  - 처음 계획은 dev만이었지만, dev에서는 후보 원천이 36개뿐이어서 v4가 쓰지 않은 test 분할을 더했다.
  - 뽑는 규칙은 v4와 같다(`abcd_build.claim_of`, 술어당 최대 20개, seed 11).
  - 일·월·년이 다 있는 날짜가 나오는 발화와, 구매를 부인하는 발화는 제외했다(1개 제외).
  - 결과는 **원천 59개**다(owns_item 20, promised_discount 19, paid_deposit 11, reserved_item 7, completed_errand 2). v/n/d 세 판으로 시나리오 **177개**를 만들었고, 원천은 v4와 겹치지 않는다.
  - v4와 같은 방식으로 변환했다: 가게 장부 하나, 손님 교체, 정답 분리, 발화 속 이름·주문번호 치환(8개 발화).
- **개발 세트 (탐색)**: v4의 시나리오 252개다. 단서표를 설계할 때 이 데이터의 실패 사례를 참고했으므로 결과를 탐색용으로만 보고한다.

## 실행
- **조건 수와 seed**: seed 11/29/47. 모델과 서버 설정은 v4와 같다.
- **검증 세트**: 기존 결정표(F-M1P1)를 시나리오 177개 × seed 3개 = 531회 돌린다. 그 기록에서 재확인이 발동하는 (시나리오, seed)만 F-M1P1RV로 다시 돌린다.
- **개발 세트**: v4의 F-M1P1 기록에서 재확인이 발동하는 경우만 F-M1P1RV로 돌린다.
- **발동하지 않는 경우**: RV의 결정은 같은 seed의 F-M1P1 결정과 같다고 본다. 이 전제는 시범 실행에서 직접 확인한다.
- **fail-closed 비교값**: F-M1P1 기록에서 오프라인으로 계산한다. 발동하면 증거 요구, 아니면 기존 결정이다.

## 지표 (확증은 검증 세트만)
분석 단위는 주장 턴이다. 원천마다 판과 seed를 평균한 뒤, 짝지은 sign-flip을 20,000회 한다. 신뢰구간은 bootstrap 5,000회로 구한 95% 구간이다.
- **주 지표**: 정확도(v·n·d 전체), RV 대 F-M1P1. 양측 α = .05.
- **부 지표 (Holm 보정)**:
  - (a) n 수용률, RV 대 F-M1P1
  - (b) v 과잉 거절률, RV 대 fail-closed
  - (c) d 반박률, RV 대 F-M1P1
- **안전 조건**: n 수용률 차이(RV − F-M1P1)의 95% CI 상한이 2%p 이하.
- **채택 규칙**: 주 지표 p < .05, RV의 정확도가 더 높음, 안전 조건 충족. 셋을 모두 만족해야 한다.
- **기술 통계**:
  - 발동 수(판별)
  - 재질문이 술어를 고른 수와 그중 정답 술어인 수
  - 재질문이 모두 거짓인 수
  - 기존 결정표 대비 고친 결정과 새로 틀린 결정
  - RV의 첫 단계 NLU가 기존과 같은 비율
  - 개발 세트의 같은 지표

## 해석 규칙
- 이 장부는 합성이고, '믿기'는 술어와 날짜가 모두 맞을 때만 나온다. 따라서 안전 조건을 통과하더라도 실제 상점 장부에서도 안전하다는 뜻은 아니다. 이 점을 한계로 보고한다.
- 검증 세트는 원천이 59개로 v4보다 작다. 효과는 발동 사례에 몰려 있으므로, 발동 수와 함께 해석한다.

## 중단 규칙
시범 실행은 원천 H001, H021, H041, H051 × v/n/d × seed 11로 한다. F-M1P1 12회와 RV 12회를 돌린다. 다음 중 하나라도 해당하면 멈춘다. 시범 결과는 본 실행에 포함한다.
- 생각 과정 누출
- 영어가 아닌 응답
- 날짜 줄 누락
- **발동하지 않은 RV 실행의 결정이 F-M1P1과 다름** (재현성 전제가 깨진 경우)
- 발동하지 않은 시범 실행이 0개라서 재현성을 확인할 수 없음
