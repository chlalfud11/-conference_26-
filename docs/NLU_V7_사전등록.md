# NLU V7 실험 사전등록 (fail-closed 2단계)

작성: 2026-10-16. 이 문서와 `nlu_failclosed.py`는 새 문장 세트 5가 만들어지기 **전에** 봉인한다(`logs/nlu_failclosed/prompt_freeze.json`).

## 1. 배경

- 2단계 방식(V5, V6)은 사전등록 검정 두 번에서 같은 경향을 보였다. 부탁을 주장으로 읽는 저→고 오독은 거의 없어졌지만(111→6), 거짓 주장을 놓치는 고→저 오독은 늘었다(5→70). 주 검정은 두 번 모두 유의하지 않았다(p=0.084, 0.070).
- 원인은 1단계가 "거래 주장인가?"를 물어서, 확실하지 않은 말을 none 쪽으로 보낸다는 점이다. "그 장화 원래 제 거예요" 같은 명시적 주장도 놓쳤다(`results/bottleneck/gated_report.md`).

## 2. 가설

1단계 질문을 "확실히 주장이 아닌 말인가?"로 뒤집고, 애매하면 2단계로 보내면(fail-closed) 고→저 오독이 V5보다 줄어든다. 동시에 저→고 오독은 B보다 적게 유지된다.

## 3. 조건

- **B**: 원본 지시문, 지금 말만 본다.
- **V5**: 봉인된 `nlu_twostage.v5`이며 바꾸지 않는다.
- **V7**: 1단계 `FC_INSTRUCTION`에서 plain / rumor / maybe_claim 중 하나를 고른다. 확실하지 않으면 maybe_claim이고, 출력을 해석하지 못해도 maybe_claim으로 처리한다.
  - plain이면 none, rumor이면 heard_rumor다.
  - maybe_claim이면 2단계로 V1 호출을 한다(문맥 없음). 2단계 결과가 그대로 최종 판정이다.
- 1단계 예시 7개 중 plain은 3개, rumor는 1개, maybe_claim은 3개다. 문장은 새로 썼다.
- 모델, seed(11, 29, 47), 2단계 지시문, 스키마, 정책은 그대로 둔다.

## 4. 새 문장 세트 5

- 작성자는 이전 세트, 프롬프트, 결과를 보지 않은 별도 작성 에이전트이고, 세트4와 같은 브리프를 받는다.
- 구성은 50 대화 × 4줄 = 200줄이고, 200줄 모두 서로 다른 문장이어야 한다. 유형 목표는 claim 50, insist 44, rumor_after_claim 34, none 45, rumor 27이다.
- 상태는 `draft_pending_user_approval`이다. 구성만 점검하고 봉인한다.

## 5. 지표와 검정

- 단위: 줄 × seed 판정 1회의 위험도(고/저) 일치 여부.
- **주 검정**: V7과 B의 차이. 대화 50개 단위 부호뒤집기 순열검정(양측, α=0.05)을 쓰고 `nlu_confirm.sign_flip` 규칙을 따른다. 부트스트랩 CI는 10,000회로 구한다.
- **부 검정**: V7 vs V5. 기술 결과로만 보고한다.
- 기술 통계: 고→저, 저→고, 유형별 정확도, 2단계 호출 수, 지연 중앙값.

## 6. 판정 규칙

**V7 권장**: 주 검정 p<0.05, 차이>0, V7의 고→저 건수 ≤ B의 고→저 건수를 모두 만족할 때.

## 7. 종료 규칙

정해진 호출(200줄 × 3 seed × 3조건)을 1회만 실행한다. 중단되면 빠진 호출만 이어서 실행한다. 결과를 보고 무엇도 바꾸지 않는다. null 결과도 보고한다.

## 8. 미리 밝히는 한계

1. 작성자는 언어 모델 에이전트이고 라벨은 독립 검수를 받지 않았다.
2. V7 아이디어는 세트3·4 결과를 보고 나왔다. 평가에는 그 뒤에 만든 세트5를 쓴다.
3. 2단계(V1)가 고위험 주장을 none으로 읽는 오독은 V7로 막을 수 없다.
4. 줄 단위 NLU 평가이며 대사와 라이브 대화는 측정하지 않는다.
