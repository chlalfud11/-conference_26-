# NLU 2단계 실험 사전등록 (V5 vs B)

작성: 2026-10-15. 이 문서와 `nlu_twostage.py`는 새 문장 세트 3이 만들어지기 **전에** 봉인한다(`logs/nlu_twostage/prompt_freeze.json`).

## 1. 배경

- 확인 실험(세트2)에서 V1은 원본 B보다 나쁘지 않다는 것을 보이지 못했다(p=0.302). 소문 판별은 좋아졌지만 '주장 없음'을 맞힌 줄이 B 90/135에서 V1 52/135로 줄었다.
- 잘못 읽힌 '주장 없음' 줄에서 모델은 `speech_act`를 request·question으로 맞게 적고도 `claim_predicate`에는 고위험 술어를 적었다(`results/bottleneck/none_analysis.json`). 한 번의 호출로 다섯 칸을 동시에 채우는데, 칸끼리 일관되도록 강제하는 장치가 없다.
- 이 상태에서 화행을 근거로 술어를 지우는 코드 규칙은 이미 기각됐다(B 301→201). 화행 칸도 믿을 수 없기 때문이다.

## 2. 가설

판단을 두 번으로 나누면 '주장 없음' 오독이 줄어든다. 첫 호출은 "과거 거래 주장 / 소문 / 아님" 중 하나만 고르고, 거래 주장일 때만 두 번째 호출이 술어를 고르게 한다.

## 3. 조건

- **B**: 원본 지시문(`runner.NLU_INSTRUCTION`), 지금 말만 본다.
- **V1**: 출처 정의와 예시 11개(`nlu_improve.V1_INSTRUCTION`), 지금 말만 본다.
- **V5**: 1단계 `GATE_INSTRUCTION`(3지선다, 예시 7개 중 none 4개)을 거친다. 결과가 `transaction`이면 2단계로 V1 호출을 한다. `rumor`이면 heard_rumor, `none`이면 none으로 둔다. 두 단계 모두 지금 말만 본다.
- 1단계 예시 문장은 기존 세트 문장을 복사하지 않고 새로 썼다.
- 모델, seed(11, 29, 47), 온도, 스키마, 정책은 같다.

## 4. 새 문장 세트 3

- 작성자는 이전 세트, 프롬프트, 결과를 보지 않은 별도 작성 에이전트다. 정의와 구성 규칙만 받는다.
- 크기와 구성은 세트2와 같다. 대화 50개 × 손님 발화 4줄 = 200줄이다. 유형은 claim, insist, rumor_after_claim, none, rumor이고 비율은 세트2와 비슷하게 맞춘다.
- 상태는 `draft_pending_user_approval`이다. 작성 후에는 구성만 점검하고 문장과 라벨은 고치지 않은 채 봉인한다.

## 5. 지표와 검정

- 단위: 줄 × seed마다 조건별 판정 1회. V5는 호출이 1~2번이지만 판정은 1회로 센다. 지표는 위험도(고/저) 일치 여부다.
- **주 검정**: V5와 B의 위험도 정확도 차이. 대화 50개를 단위로 한 부호뒤집기 순열검정(양측, α=0.05)을 쓴다. 정확 계산과 표본 추출 규칙은 `nlu_confirm.sign_flip`과 같다. 부트스트랩 95% CI는 10,000회로 구한다.
- **부 검정 1개**: V5 vs V1. 보정은 하지 않는다(1개뿐이다). 기술 결과로 보고한다.
- 기술 통계: 술어 정확도, 고→저, 저→고, 유형별 정확도, V5의 2단계 호출 수, 지연 중앙값.

## 6. 판정 규칙

**V5 권장**: 주 검정 p<0.05, 차이>0, V5의 고→저 건수 ≤ B의 고→저 건수를 모두 만족할 때.

## 7. 종료 규칙

정해진 호출(200줄 × 3 seed × 3조건)을 1회만 실행한다. 중단되면 빠진 호출만 이어서 실행한다. 결과를 보고 문장, 라벨, 프롬프트, seed를 바꾸거나 추가하지 않는다. null 결과도 모두 보고한다.

## 8. 미리 밝히는 한계

1. 작성자는 언어 모델 에이전트이고 라벨은 독립 검수를 받지 않았다.
2. 1단계 지시문은 세트2의 오독 패턴('주세요/얼마/있어요?')을 보고 썼다. 세트3은 그 뒤에 만들어지므로 평가 자체는 오염되지 않는다. 다만 개선 아이디어는 이미 본 자료에서 나왔다.
3. V5는 문맥을 보지 않는다. 지시어만 있는 되풀이 발화("그거 아직 있죠?")는 V1과 같은 조건에서 불리하다.
4. 줄 단위 NLU 평가다. 대사와 라이브 대화는 측정하지 않는다.
5. 지연은 노트북 환경 기준이다.
