# ABCD 장부 개선 실험 사전등록

계획: `.omo/plans/abcd-ledger-v2.md`. 실행 전 봉인한다(`results/abcd2/prereg_seal.json`).

## 문제와 가설
- 이전 실험(L0)에서 M1P0은 장부에 기록이 있는 주장 252턴 중 24턴(9.5%)만 받아들였다.
- 받아들이지 않은 228턴 중 134턴은 대사에서 기록을 봤다고 말했다.
- 가장 많이 요구한 것은 영수증(150)과 주문번호(116)였다.

가설은 네 가지다.
- H1 신원 공백: 장부가 "this customer"라고만 쓰고, 누구인지와 본인 확인 여부가 없어서 기록과 손님을 잇지 못한다.
- H2 기록의 모호함: 주문번호, 날짜, 금액이 없어 손님 말과 대조할 수 없다.
- H3 지시의 편향: 페르소나가 "장부만 믿는다"고 하고 예시 3개 중 2개가 영수증을 요구하며, 일치하는 기록이 증거라는 말이 없다.
- H4 기록과 주장의 불일치: 장부 상품이 손님이 말한 상품과 다를 수 있다. 장부 v2 생성 결과 불일치 0건이라 H4는 L1/L2에서 통제된다.

## 조건
- L0: 기존 실행(한 줄 장부, `results/abcd/runs`). 새로 돌리지 않는다. 시범 실행에서 시범 시나리오 10개를 다시 돌려 결정이 같은지 확인한다.
- L1: 장부 v2(`abcd_ledger.py`, 168개, 해시 479f8ee2…). 손님 이름·계정·회원 등급·본인 확인 완료·주문(번호, 날짜, 상품, 금액, 상태)·결제·반품/프로모 코드 행을 담는다. 페르소나와 지시는 L0와 같다.
- L2: L1 + 지시 수정(`npc_en.PERSONA_FIX`, `DECIDE_FIX`). "확인된 손님의 주장과 일치하는 장부 기록은 그 자체로 증거다. 그때는 영수증이나 주문번호를 요구하지 않는다"는 문장과, 기록을 받아들이는 예시 대사 1개를 추가한다.
- 실행: M1P0 × {L1, L2} × seed 11/29/47 × 168개 = 1,008회, M1P1 × L2 × seed 11 × 168개 = 168회. 총 1,176회.
- 모델은 Ornith-1.5-9B-Q4_K_M(`--reasoning-budget 0`), temperature 0.2, top_p 0.9. 시나리오 문장은 승인된 것 그대로다.

## 지표 (주장 턴 = 마지막 턴, 원천 84개 단위로 seed 평균, 짝지은 sign-flip 20,000회)
- 주 지표: v 버전 과잉 거절(결정이 accept_as_belief가 아님), L0 대 L2, 양측 alpha .05.
- 부 지표(Holm): (a) L0 대 L1, (b) L1 대 L2, (c) 안전성: n 버전 TCAR의 L2 − L0.
- 안전 한계: (c)의 bootstrap 95% CI 상한이 10%p 이하이면 통과한다. 넘으면 L2는 "지나치게 잘 믿는" 것으로 판정한다.
- 기술 통계: 미수용 중 기록을 봤다고 말한 수, 요구한 증거 종류, v에서 "기록을 못 찾는다"는 발화 수, n에서 "기록을 본다"는 거짓 인정 발화 수, 술어별 수용률. M1P1 L2와 M1P1 L0(seed 11)의 대사 비교.

## 해석 규칙
- (a)가 유의하면 H1/H2를, (b)가 유의하면 H3를 지지한다.
- 채택: 주 지표 p < .05이고 L2의 과잉 거절이 더 낮으며 안전 한계를 통과할 때.

## 중단 규칙
- 시범(시범 시나리오 10개 × L1/L2 × M1P0 × seed 11)에서 생각 과정 누출이 있거나, 영어가 아닌 응답이 있거나, 장부 블록이 프롬프트에 빠지면 본 실행 전에 멈춘다.
- L0 재실행 결정이 저장된 결정과 10개 중 8개 미만으로 같으면 L0 비교가 무효이므로 사용자에게 묻는다.
