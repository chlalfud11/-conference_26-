# NLU V6 실험 사전등록 (2단계 + 코드 게이트 문맥)

작성: 2026-10-16. 이 문서와 `nlu_gated.py`는 새 문장 세트 4가 만들어지기 **전에** 봉인한다(`logs/nlu_gated/prompt_freeze.json`).

## 1. 배경

- V5(2단계)는 세트3에서 '주장 없음'을 135/135 맞혔고, 부탁을 주장으로 읽는 저→고 오독은 0회였다. 그러나 고→저 오독이 62회로 B(5회)보다 많았고, 주 검정도 유의하지 않았다(p=0.084, `results/bottleneck/twostage_report.md`).
- 고→저 62회 중 48회는 문맥이 없어 1단계가 none으로 판정한 되풀이 발화였다("그거 확인해 주시면 안 돼요?" 등).
- 코드 게이트(`nlu_confirm.MARKERS`)는 세트2에서 소문 판별을 망치지 않았다(102/102).

## 2. 가설

V5의 1·2단계에 코드 게이트 문맥을 붙이면 되풀이 발화의 고→저 오독이 줄어든다. 동시에 V5의 '주장 없음' 개선은 유지된다.

## 3. 조건

- **B**: 원본 지시문, 지금 말만 본다.
- **V5**: 봉인된 `nlu_twostage.v5`. 바꾸지 않는다.
- **V6**: 먼저 `nlu_confirm.gate()`로 게이트 작동 여부를 정한다. 작동 조건은 앞 줄이 있고 지금 말에 MARKERS가 있는 것이다.
  - 게이트가 켜지면 1단계(`GATE_INSTRUCTION` + V2 접미사)와 2단계(V2 형식) 모두에 직전 손님 말 2개를 넣는다.
  - 게이트가 꺼지면 V5와 같다.
- 정규식, 지시문, 모델, seed(11, 29, 47), 스키마, 정책은 모두 그대로 둔다. 새로 쓴 지시문은 없다.

## 4. 새 문장 세트 4

- 작성자는 이전 세트, 프롬프트, 결과를 보지 않은 별도 작성 에이전트다. 정의와 구성 규칙만 받는다.
- 구성은 세트3과 같다. 대화 50개 × 4줄 = 200줄이고, 유형 목표는 claim 50, insist 44, rumor_after_claim 34, none 45, rumor 27이다.
- 세트3은 서로 다른 문장이 109/200개뿐이었다. 그래서 이번에는 **200줄이 모두 서로 다른 문장**이어야 한다는 구성 규칙을 브리프에 추가한다. 이 규칙은 결과를 보기 전에 정한다.
- 상태는 `draft_pending_user_approval`이다. 작성 후 구성만 점검하고 봉인한다.

## 5. 지표와 검정

- 단위: 줄 × seed 판정 1회의 위험도(고/저) 일치 여부.
- **주 검정**: V6와 B의 차이. 대화 50개 단위 부호뒤집기 순열검정(양측, α=0.05)을 쓰며 `nlu_confirm.sign_flip` 규칙을 따른다. 부트스트랩 CI는 10,000회로 구한다.
- **부 검정**: V6 vs V5. 기술 결과로만 보고한다.
- 기술 통계: 고→저, 저→고, 유형별 정확도, 게이트 작동 수, 2단계 호출 수, 지연 중앙값.

## 6. 판정 규칙

**V6 권장**: 주 검정 p<0.05, 차이>0, V6의 고→저 건수 ≤ B의 고→저 건수를 모두 만족할 때.

## 7. 종료 규칙

정해진 호출(200줄 × 3 seed × 3조건)을 1회만 실행한다. 중단되면 빠진 호출만 이어서 실행한다. 결과를 보고 무엇도 바꾸지 않는다. null 결과도 보고한다.

## 8. 미리 밝히는 한계

1. 작성자는 언어 모델 에이전트이고 라벨은 독립 검수를 받지 않았다.
2. V6 아이디어는 세트3 결과를 보고 나왔다. 평가는 그 뒤에 만든 세트4로 한다.
3. MARKERS에 없는 지시 표현("장부 한번 보세요" 등)이 있는 되풀이 발화는 게이트가 켜지지 않는다.
4. 줄 단위 NLU 평가다. 대사와 라이브 대화는 측정하지 않는다.
