# M1P2G: 출처가 명시된 실제 엔진 근거 추가 실험

사용자의 “진행 해”를 정확한 근거를 사용하는 별도 54회 검증 선택으로 받아들였다.
이 문서는 신규 추론 이전에 작성하며 결과를 보고 조건을 수정하지 않는다.
기존 목표 도구는 미완료 목표 교체를 거부하므로, 기존 목표를 이어가되
이번 사용자 선택으로 변경된 범위와 검증 기준을 이 문서에 기록한다.

## 보존할 실험

기존 M1P2는 오류가 있는 근거 템플릿을 포함한 별도 조건으로 그대로 보관한다.
54회 결과를 수정하거나 교체하지 않는다. 기존 여섯 조건 324레코드의 전체 지문:

`fca27a574b23ac6fb04271438329b541fe792b8a28bdd87d93ad001056437033`

새 조건 이름은 M1P2G다. M1P2를 고쳐 같은 이름으로 재실험하지 않는다.
M1P1/M1P2/M1P2G의 차이는 대사 생성에 전달하는 추가 문구다.
기억 필드, NLU 지시문, 정책 함수, 거래 처리, 시나리오, 평가 코드는 유지한다.

## 새 근거의 정확한 의미

근거 블록은 JSON으로 다음 두 종류를 분리한다.

1. `world_truth`: 해당 턴 대사 생성 직전 `GameEngine.world()`의 현재 값 전체.
   출처는 `game_engine`이다. 예약, 재고, 인벤토리, 골드는 기록된 수량 그대로다.
2. `policy_inputs`: NLU에서 추출한 주장 술어·대상, 파생 위험도, 시나리오의 증거 상태·
   신뢰도·상태 모순. 각각의 출처를 표시하고, `evidence_verified`는
   입력 증거가 `verified`일 때만 참이다.

`truth_predicate`, 정답 라벨, 금지 표현 정규식은 근거 블록에 넣지 않는다.
NLU가 찾은 대상명이 불완전해도 임의로 품목을 보정하지 않는다.
모든 품목의 실제 수량을 제공하므로 대상명을 정확히 일치시켜야만 수량이 보이는
기존 M1P2의 제약을 피한다.

정책이 소문을 믿기로 했다는 이유만으로 증거가 검증됐다고 쓰지 않는다.
예약 수량과 실제 거래 상태는 엔진의 값으로 확인하지만, 엔진에 표현되지 않은
약속·선금 기록의 부재를 예약 수량만 보고 단정하지 않는다.
증거 상태는 현실 세계의 독립 검증 결과가 아니라 시나리오 오라클 입력임을 명시한다.

기존 구조화 기억은 NPC Belief를 `검증: verified`로 표시한다.
이 표현은 이번 조건에서 바꾸지 않는다. 추가 근거 블록에서 이 표시는 정책에 의한
승격 기록이며 외부 증거의 검증 완료와 같지 않다고 구분한다.
따라서 이 실험은 기존 기억 표현 자체를 교정한 비교가 아니다.

## 말투 예시

새 조건에만 사실 확인을 지어내지 않는 예시를 사용한다.
증거 요구는 증빙 제시 요청, 보류는 판단 유보, 믿음 수용은 기억하겠다는 응답으로 쓴다.
반대 장부나 확인된 증거가 존재한다고 예시 문장 자체가 단정하지 않는다.
이 예시와 근거 블록의 최종 문구는 첫 신규 추론 전에 소스 지문으로 고정한다.
두 변경을 함께 적용하므로 어느 쪽의 개별 효과인지는 분리되지 않는다.

## 실행

- 기존과 같은 EXAONE-3.5-2.4B-Instruct-Q4_K_M.
- temperature 0.2, top_p 0.9, seed 11/29/47, context 4096.
- 동일한 시나리오 18개 × seed 3개 = M1P2G 54회.
- 권위 로그는 기존 324회에 추가해 총 378 유일 레코드가 된다.
- 첫 스모크는 별도 로그에 저장하며 권위 실험 54회를 대체하지 않는다.
- 완료 기록을 선별해서 다시 생성하지 않는다. 중단 시 미완료 run_id만 재개한다.
- 외부 LLM API, 출력 검증기, 새로운 NLU 파이프라인은 사용하지 않는다.
- 결과 방향과 관계없이 기준②, CCR, TCAR, 결정 일치율과 전체 짝지은 대사를 보고한다.
- 플래그 소실과 신규 플래그를 의미적 오류의 수정·발생으로 단정하지 않는다.
- 기존 4페이지 논문/PPT에는 자동 반영하지 않고 별도 결과 보고서로 전달한다.

## 사전 검증 기준

### G1: 근거 자료가 입력과 엔진 상태에 충실함

관련 pytest에서 예약 수량 0/양수, 재고와 거래 후 인벤토리, 고신뢰 미검증 소문,
검증된 증거, 반대 증거를 검사한다. JSON을 파싱해 엔진과 입력 값을 비교한다.
미검증 소문의 수용은 허용하되 `evidence_verified=false`가 유지돼야 한다.
프롬프트의 자연어 문장을 테스트로 고정하지 않는다.

### G2: 기존 여섯 조건의 조립 결과 보존

S05_v1 seed11에서 기존 원자료의 NLU와 응답을 고정 재생하고 실제 로컬 임베딩을 사용한다.
과거에 저장된 48개 `prompt_hash`가 모두 일치해야 한다.
이는 새 샘플링 출력의 결정론을 검증하는 기준이 아니다.
기존 최초 새 샘플링 회귀 21/24 실패 기록도 보존한다.

### G3: 추론 이전 동결

런타임 전체 `.py`, 시나리오 전체 JSON, 관련 테스트, 이 계획과 감사 스크립트의
SHA256을 신규 추론 이전에 저장한다. 모델 지문과 서버 실행 옵션도 기록한다.
원본 324레코드 지문과 기존 6행 집계의 값을 함께 보존한다.
실제 스모크에서 JSON 근거의 출처와 `policy_engine` actor를 확인한다.

### G4: 54회 완료 및 비교

378 유일 레코드, 조건별 54회, 결과표 7행이어야 한다.
기준②는 기존 평가 함수와 동일한 183개 턴에서 세 조건을 비교한다.
432턴의 NLU 술어와 결정 차이도 직접 집계한다.
정책 입력이 같을 때 결정이 같은 것은 함수의 성질이지만,
같은 seed만으로 모든 NLU 입력이 같다고 가정하지 않는다.

### G5: 보존과 검증

동결된 소스와 시나리오 해시, 원본 324줄 접두부 해시가 마감 시점에도 같아야 한다.
기존 6조건의 CSV 모든 열이 보존본과 같아야 한다. 관련 테스트를 통과해야 한다.
기존 논문 수치 검증은 기존 논문 입력 5행으로 실행해 오류 0건을 확인한다.
미설치 정적 진단 도구는 실행했다고 주장하지 않는다.

### G6: 결과 보고와 정리

변경 효과의 귀속 한계와 탐지기 한계를 포함한 보고서를 저장한다.
추론 서버와 포트를 해제하고 임시 산출물을 정리한 영수증을 노트패드에 기록한다.

G1~G6의 근거와 별도 보고서가 완성되면 결과 방향에 관계없이 종료한다.
