NPC가 손님 말을 듣고 답하기까지 (현재 최종 조건 M1P3)

코드 기준: npc/runner.py run_dialogue(), 조건 설정 decider=decision_table_sourced, output=engine_renderer
언어모델(EXAONE 2.4B) 호출코드·게임 엔진기억감사 기록만
0손님 말 입력"저번에 잼 두 병 예약했잖아요. 주세요." → 기억에 '손님' 발화로 저장
▼
1귀: NLU (언어모델 호출 ①) 손님 말 한 줄만 보고 JSON으로 구조화합니다. 형식이 강제됩니다(json_schema).
→ intent, speech_act, claim_predicate(예: reserved_item), claim_object(예: 잼), confidence
▼ claim_predicate만 다음 단계로 (speech_act는 쓰이지 않음)
2위험도 판정 (코드) risk_of(): 예약·선금·약속·심부름·소유 → 고위험, 소문·없음 → 저위험.
주장이 있으면 엔진 장부에 주장(claim)으로 저장합니다(사실 아님).
+
게임이 아는 값 증거 상태(검증됨/없음/모순), 손님 신뢰도(0~3), 상태 모순 여부 — 언어모델이 정하지 않습니다.
▼
3문지기: 승격 정책 (코드, 결정표) 모순 → reject · 반박 증거 → dispute · 고위험+증거 없음 → request_evidence · 고위험+검증 → accept · 저위험+신뢰≥2 → accept · 그 외 → defer
같은 입력이면 항상 같은 결정. 수용(accept)일 때만 엔진에 '믿음'이 생김
▼
4입: 대사 후보 (언어모델 호출 ②) 페르소나 + 가게 상태 + 기억 + 엔진 근거(JSON) + 정책 결정을 받아 1~2문장을 씁니다.
"판단을 뒤집지 마라"
→
원문은 감사 로그로만 raw_response에 저장. 손님에게 보이지 않고 기억에도 들어가지 않습니다.
(예: "예약하신 잼 준비해 드릴게요" ← 오염 후보)
▼
5최종 대사 조립 (코드, 엔진 렌더러) make_speech_plan → render_speech_plan: 고정 템플릿 + 엔진의 실제 재고·가격·예약 수량 슬롯으로 문장을 만듭니다.
→ "자네, 그 말씀을 뒷받침할 증거를 보여주겠어요?" (거래 행동이 있으면 engine.buy 결과 반영)
▼
6손님에게 출력엔진 사실로만 만든 문장
+
기억 갱신최종 대사만 '도르만' 발화로 저장 → 다음 턴의 [기억]
핵심: 언어모델은 ①귀와 ④입 두 번만 호출되고, 결정(③)과 손님이 듣는 말(⑤)은 코드가 정합니다. 그래서 최종 오염 탐지가 0/183입니다. 다만 ①에서 말을 잘못 알아들으면(위험도 정확도 약 .83) ③이 틀린 입력으로 정확히 집행하게 되며, 이것이 현재의 병목입니다. 세계의 사실(World Truth)은 오직 게임 엔진만 바꿉니다.
