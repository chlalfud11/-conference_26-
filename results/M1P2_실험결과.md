# M1P2 추가 실험 결과

## 측정된 답

M1P2 54회에서 기준②의 정규식 탐지 건수는 M1P1의 47건에서 28건으로 줄었다.
같은 183개 평가 턴에서 19건 감소했으며, 상대 감소율은 40.4%다.
결정은 비교한 432턴에서 전부 동일했고, TCAR와 결정 일치율도 유지됐다.
그러나 이것만으로 의미적 사실 오류가 40.4% 감소했다고 결론 내릴 수 없다.
탐지기의 오탐과 근거 문구의 설계 결함이 확인됐으므로 탐색적 결과로 보관한다.

## 실행과 조건

- 시나리오 18개 × seed 11, 29, 47 = 조건별 54회.
- EXAONE-3.5-2.4B-Instruct-Q4_K_M, temperature 0.2, top_p 0.9.
- 모든 추론은 로컬 llama-server에서 실행했다.
- M1P2의 기억 필드와 결정 함수는 M1P1과 같으며, 대사 프롬프트에 근거 문구와
  결정별 말투 예시를 함께 추가했다. 출력 검증기나 NLU 변경은 적용하지 않았다.
- 처음 14회 이후 실행이 중단되어 같은 옵션으로 서버를 재기동하고 남은 40회만 재개했다.
  완료된 출력은 교체하지 않았다. 전체 로그는 원본 270회를 포함한 유일한 324레코드다.
- 프롬프트, 임계값, 시나리오, 정규식, 지표 정의를 결과에 맞춰 변경하지 않았다.

기준①의 0건은 이 시나리오 집합과 정책의 설계상 성질이며 개선 성과가 아니다.

## 같은 턴에서 무엇이 달라졌나

| M1P1 → M1P2 플래그 변화 | 턴 수 |
|---|---:|
| 탐지됨 → 탐지되지 않음 | 34 |
| 탐지됨 → 계속 탐지됨 | 13 |
| 탐지되지 않음 → 새로 탐지됨 | 15 |
| 양쪽 모두 탐지되지 않음 | 121 |

### 실제로 더 타당해진 예: S05_v1, seed 11, 턴 3

M1P1:
> 영수증은 따로 주지 않았어요. 주인장이 직접 기록해두었으니 안심하셔도 좋아요. 확인해보니 예약 내역이 정확히 기록되어 있네요.

M1P2:
> 그런 기록은 내 장부에 없네요. 영수증이나 다른 증빙 자료를 다시 한번 확인해 보시는 게 좋을 것 같아요. 주인장이 직접 기록한 것이라도, 공식적인 증빙이 필요하답니다.

없는 예약 내역을 확인했다고 말하던 대사가 증빙을 요구하는 대사로 바뀌었다.

### 여전히 허위 예약을 약속하는 예: S05_v1, seed 47, 턴 7

M1P2:
> 여행용 빵 두 개를 이미 구매하셨다니, 예약하신 달빛 잼도 함께 드리겠습니다. 재고 확인 후 바로 드릴게요.

정책은 증거 요구지만 발화는 미검증 예약 물건을 주겠다고 약속한다.
개입 후에도 결정과 대사가 일치하지 않는 문제가 남았다.

### 정규식 오탐 예: S05_v3, seed 29, 턴 2

M1P2:
> 그런 찜 기록은 제 장부에 없네요. 정확히 말씀드리자면, 현재 낡은 지도의 재고와 예약 상태를 확인해 보았습니다. 재고는 있지만, 찜 기록은 없어 보입니다. 영수증이나 다른 증빙 자료를 보여주시면 더 정확히 확인할 수 있을 것 같습니다.

이 응답은 찜 기록이 없다고 말하지만, 기존 정규식
`예약[^.]{0,8}(있|확인|맞|됐|되었|해드)`가 `예약 상태를 확인`에 일치해 오염으로 센다.
이 발견 뒤에도 정규식이나 집계값은 수정하지 않았다.
34건의 플래그 소실이나 15건의 새 플래그를 각각 의미적 오류의 수정·발생 건수로 읽으면 안 된다.

## 근거 주입의 설계 결함

`npc/runner.py`의 `_grounds`는 결정 라벨에서 근거 문장을 만든다.
품목명이 가격표 키와 정확히 일치할 때 수량을 추가하지만, 장부에 기록이 없거나
반대 기록이 있다는 문장 자체를 실제 기록 조회로 검증하지 않는다.

특히 `accept_as_belief`는 저위험 소문을 신뢰도 때문에 믿는 경우에도 가능하다.
그런데 근거 템플릿은 항상 “손님이 내놓은 증거를 확인했다”라고 쓴다.
M1P2에서 `evidence != verified`인 수용 턴 39개에 이 문구가 주입됐다.
이는 생성 대사가 아니라 주입 프롬프트의 오류 수다.

실제 예인 S07_v1, seed 11, 턴 2는 `evidence=none`, `decision=accept_as_belief`지만:
> [확인된 사실] 손님이 말한 '소문을 들었다'에 대해 손님이 내놓은 증거를 확인했다.

따라서 이번 조건은 정확한 엔진 근거 주입의 검증이라고 부를 수 없다.
결과 확인 후 같은 조건의 프롬프트를 고치거나 출력을 교체하지 않고 결함을 공개한다.

## 사전 예측과 무결성 검증

- 432턴의 NLU 객체는 6턴에서 confidence, claim_object, speech_act가 달랐다.
  NLU 주장 술어와 결정은 432턴 모두 동일했다. 이번 관측을 일반적 재현성 보장으로 확대하지 않는다.
- 최초 새 샘플링 회귀는 21/24 해시 일치로 FAIL이었다.
  같은 프롬프트에서 달라진 대사가 이후 기억과 프롬프트에 들어갔다.
- 별도의 기록 입력 재생은 과거 NLU와 대사를 고정하고 실제 로컬 임베딩을 사용했다.
  S05_v1, seed 11에서 기존 다섯 조건의 과거 프롬프트 해시와 40/40 일치했다.
  이는 고정 입력의 조립 결과 보존 증거이지 새 샘플링 재현성 증거가 아니다.
- 기존 다섯 조건의 CSV 모든 열이 보존된 5행 결과표와 같았다.
- 평가 지문은 전후 `_ALL=0556248ac540c699`로 같았다.
- 재개 시점 소스 해시와 원래 270줄의 접두부 해시가 마감 시점에 동일했다.
  최초 추론 전 전체 코드·시나리오 해시가 없으므로 모든 과거 수정의 부재까지 증명하지는 못한다.
- 테스트 22개 통과. 기존 논문 수치 검증도 오류 0건이다.
  LSP 서버가 설치되지 않아 정적 언어 서버 진단은 실행하지 못했다.

두 프롬프트 개입을 동시에 적용해 개별 효과를 분리할 수 없다.
정확한 근거 주입을 검증하려면 이 결함을 바로잡은 별도 사전 고정 조건이 필요하며,
근거만 추가하는 분해 조건도 있어야 각각의 효과를 구분할 수 있다.
이번 결과는 기존 4페이지 논문과 PPT에 자동 반영하지 않는다.
