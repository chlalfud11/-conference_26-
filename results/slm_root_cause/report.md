# SLM 허위 단정: 원인 분리 실험 결과

## 결론

과거 NPC의 자유 생성 대사를 다음 입력에서 빼는 H가 이번 파일럿의 사전 선택 기준을 충족했다.
정책-대사 모순은 기본 8/36에서 2/36으로 줄었지만 근거 없는 사실 단정은 9/36에서
8/36으로만 줄었다. 일부 카드는 악화됐다. **자기 발화의 재입력이 오류를 증폭한다는
증거는 얻었지만, 이를 제거하면 허위 단정이 해결된다는 증거는 얻지 못했다.**

맥락 추가 NLU, 짧은 발화 계약 C, 공식 system 접두어, 증거 안내 변경 E는 채택 기준을
통과하지 못했다. 특히 짧은 계약 C는 주 판정에서 악화됐다. 권장했던 방법이 효과 없거나
악화된 결과도 그대로 남긴다. 작은 모델·Q4 양자화가 근본 원인이라고 단정할 수 없다.

의미 판정은 조건명을 숨긴 실행 에이전트의 AI 보조 감사다. 독립적인 사람의 평가가 아니다.
180개 중 36개에는 해석의 모호성이 표시됐다. 이 파일럿을 일반적인 환각률이나
전체 54회 대화 실험의 성능으로 해석하지 않는다.

## 범위와 검증

- 기존 M1P2G seed11의 12개 pre-speech 상태를 실제 runner/StructuredMemory로 재생했다.
  원래 프롬프트 해시는 12/12 일치했다. 실제 NLU와 계산된 정책을 고정했으며 정답을 주입하지 않았다.
- 오류/경계 6개: S05_v1 3·7턴, S06_v3 4턴, S07_v1 1턴, S12_v1 2턴, S06_v2 2턴.
  정상 대조 6개: S05_v1 1·6턴, S07_v1 2턴, S08_v3 2턴, S11_v1 2턴, S11_v2 2턴.
- 런타임 반복 12회 + NLU 108회 + 발화 180회 = 총 300회 완료. 고유 ID 300개이며
  실패/재샘플링은 없었다. 300개 모두 JSON 스키마에 맞고 finish_reason=stop이었다.
- 조건마다 12카드 × seed 11/29/47 = 36개다. 조건 순서를 카드·seed별 순환 배치했다.
  EXAONE-3.5-2.4B-Instruct-Q4_K_M, temperature 0.2, top_p 0.9,
  NLU 최대160/발화 최대256토큰, 기존 서버 옵션을 유지했다.
- 발화 판정 180개를 먼저 봉인한 뒤 조건 매핑을 열었다. 판정 구절·근거·모호성·판정자 정보는
  `logs/root_cause/annotations.jsonl`, 봉인 SHA는 `audit_receipt.json`에 있다.
- 관련 회귀 테스트 35개 통과. `basedpyright`가 설치되지 않아 LSP 정적 타입 검사는 미실행이다.

사전 기준: NLU는 기본보다 전체 정답 수가 늘고 인사/구매 대조군이 악화되지 않아야 한다.
발화는 근거 없는 단정/정책 모순이 줄고 다른 항목이 증가하지 않아야 하며, 검증된 주장·
미검증 소문·일반 상품 문의를 증거 없다는 이유로 일괄 거절하는 방식이면 탈락한다.
기본에 의미 오류가 없는 카드에는 개선을 주장하지 않는다.

여러 조건에 남았지만 명시적인 수용 거부와 같게 세지 않았다.

### H가 개선한 부분과 남긴 오류

S06_v3/t4의 할인 분쟁에서는 B가 세 seed 모두 “반값 할인은 이미 적용”이라고 했다.
H는 세 seed 모두 정가 거래/반값 불가를 말했다. 이 카드의 의미 오류는 3/3에서 0/3으로 줄었다.
예: B의 R133은 “반값 할인은 이미 적용되었습니다”, H의 R137은
“장부에 적힌 가격을 지키는 것이 저의 원칙 ... 반값으로 제공 ... 맞지 않아요”였다.

반대로 S05_v1/t3은 B 1/3에서 H 3/3, S06_v2/t2는 B 1/3에서 H 2/3으로 악화됐다.
H에서도 영수증을 주지 않는 가게 방침을 지어내거나 재고를 주문 증거처럼 쓰는 오류가 남았다.
NPC 발화만 제거했으며 사용자 주장·믿음·엔진 사건·현재 상태는 보존했다.
이 비교는 NPC 기록 삭제라는 입력 묶음의 효과이지 특정 문장 한 개의 인과 효과는 아니다.

### 짧은 계약은 해결책으로 검증되지 않았다

C의 평균 입력은 1,131.75토큰, B는 1,258.08토큰으로 약 10%만 짧았다.
C는 기억/예시/표현/배치를 함께 바꾸므로 길이만의 효과를 측정하지 않는다.
S12_v1/t2의 첫 예약 주장은 B에서 확인 질문으로 답했지만 C는 세 seed 모두
“예약했군요/예약하셨군요”라고 답했다. 단순 주장 수신과 예약 확인의 경계가 있어
세 판정 모두 모호성도 표시했다. 이 대사를 확정 오류로 해석하지 않더라도 C의 개선은 입증되지 않았다.

H는 주 판정 기준의 후속 후보일 뿐, 사람 판정에서도 효과가 유지된다는 결론은 아니다.

## 추론 인터페이스

서버는 llama.cpp 0.6.0/build11429/commit d81235049이며 모델 전체 SHA는
`1660a3794acc33437137faab5cb3fb2b2c4191d0a4ec991d4c31a7197cb2cdbf`다.
`/props`의 chat_template는 공식 tokenizer_config와 정확히 같았다.
`/apply-template`로 역할 구분을 렌더링했고 공식 EOS `[|endofturn|]`는 토큰361로 확인됐다.
슬롯4개가 각각4,096토큰이었다.

4개 고정 입력을 3회씩 호출한 12개 출력은 각 입력 내에서 모두 동일했다.
모든 계획 입력의 진단 렌더링을 토큰화했고 288개 호출의 API prompt_tokens가
해당 전체 렌더링 토큰 수와 모두 같았다. 입력+최대출력은 용량 이내였고,
실제 입력+출력의 최대는 1,845토큰이었다. 출력 length 종료는 300개 중0개였다.

입력 잘림을 나타내는 명시적 API 필드와 실제 생성 경로의 적용 프롬프트 trace는 없었다.
따라서 메타데이터/진단 렌더링/usage가 일관됨은 확인했지만 직접 trace를 검증했다고 쓰지 않는다.
시작 로그의 `special_eos_id is not in special_eog_ids` 경고는 보존했다.
관측된 템플릿 불일치나 잘림/종료 실패가 없어서 서버 옵션을 임의 교정하지 않았다.
반복4입력의 동일 출력은 모든 상황의 결정성을 보장하지 않는다.

## 원인별 판단과 해결 방향

| 원인 후보 | 이번 근거 | 판단/방법 |
|---|---|---|
| 자기 NPC 원문의 재입력 | H에서 정책 모순8→2, 일부 카드 악화 | 증폭 경로를 지지. 원문을 사실 근거로 재사용하지 않는 후속 조건이 우선 후보 |
| 현재 턴 NLU의 맥락 부족 | 생략 할인은 개선, 명시 주문은 악화 | 일부 오류 설명 가능, 두 턴 추가만으로 전체 문제는 해결 안 됨 |
| 범주/의도 구분 실패 | 명시 예약도 할인/보상으로 분류, 인사에도 주장 생성 | 현재 명시 주장과 생략 참조를 분리하는 인터페이스/학습 후보가 필요 |
| 올바른 정책 지시의 의미 준수 실패 | 실제 dispute인데 반값 적용 완료 생성, 짧은 계약도 미개선 | JSON 구조와 자연어 의미 준수는 별도. 계약 문구 추가만으로 해결 안 됨 |
| 믿음 수용과 증거 검증의 잘못된 표시 | 구현 결함은 확인됐으나 12카드 모두 pre-speech npc_belief 0개 | 교정 자체의 효과는 미검증. E는 안내만 바뀐 실험이며 믿음 교정 효과로 해석 금지 |
| GGUF 템플릿/문맥 문제 | 공식 템플릿 일치, 토큰 용량과 usage 일치, 정상 종료 | 관측된 실패 원인으로 지지되지 않음. 직접 생성 trace는 미확인 |
| 작은 모델/Q4 양자화/학습 부족 | 정밀도/크기/학습 비교는 실행 안 함 | 기여도 미검증. 별도 통제 비교가 필요 |

SLM은 엔진의 결정을 실행하는 규칙기가 아니라 다음 토큰을 생성하는 모델이다.
JSON 문법 제약은 필드 구조를 제한해도 문자열 안의 사실성을 보증하지 않는다.
올바른 decision을 넣었는데도 이미 할인이 적용됐다는 대사를 만드는 관측은 이 간극을 보여준다.
이는 모델 크기만의 원인이라는 주장이 아니며, 모든 오류를 자기 발화나 입력 표시에 귀속하지 않는다.

우선 권고는 H 방식의 후속 검증이다. 자유 생성 원문을 이전 NPC 대사로 넣는 대신
엔진 사건/주장 출처와 검증 상태를 보존한다. 하지만 삭제만으로 안심하지 않고 남는
예약/선금/재고 오류와 정상 대조군을 새 평가에서 함께 확인해야 한다.

NLU 맥락 추가, C 계약, 공식 접두어, E 안내 변경은 이번 결과만으로 제품에 채택하지 않는다.
믿음 표시의 의미 오류는 관측된 표현 결함으로 별도 교정할 가치가 있지만 이번 파일럿의
성능 개선으로 포장하지 않는다. 도메인 SFT/LoRA는 주장/사실 구분, 미확인 인정,
정책에 맞는 자유 발화를 배우도록 하는 후속 후보이지 이번에 검증된 해결책은 아니다.
학습/평가는 시나리오 가족별로 분리하고 이 진단 문장을 학습해 점수를 올리지 않는다.
같은 체크포인트의 높은 정밀도는 양자화, 다른 크기의 같은 계열은 대안 모델 효과의
후속 비교로 둔다. 원문 자유 생성의 완전한 무오류 보장은 학습과 별도의 출력 권한 문제다.

## 보존과 자원

기존 432회 원자료, 모델2개, 제품 코드, 시나리오18개, 평가표4개, 논문MD/PDF,
발표자료의 40개 파일 SHA256이 동결 지문과 모두 일치했다. 제품 코드/논문/기존 평가는
변경하지 않았다. 추가한 코드만 `npc/root_cause_probe.py`, `tests/test_root_cause_probe.py`다.
소유 chat 서버 PID75461와 caffeinate PID75496는 추론 완료 후 종료했고 포트8080/8081의
리스너와 두 프로세스가 없음을 확인했다. 다른 서버는 시작하거나 종료하지 않았다.
정리/보존 영수증은 `logs/root_cause/cleanup.json`에 있다.
