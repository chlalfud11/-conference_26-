# NLU 조건(B·V1·V2·V3)과 대화 기록 보고서

자동 생성: `python3 nlu_variant_record.py`. 모든 표는 원자료 로그에서 직접 만든다.
부록 A: `부록A_기존시나리오_NLU기록.md`, 부록 B: `부록B_라이브대화기록.md`.

읽는 법: 술어(무엇을 주장했나)는 예약·선금·보상약속·할인약속·심부름·소유(고위험), 소문·없음(저위험)으로 나뉜다. 정책은 위험도만 보므로 위험도를 맞히면 결정도 맞는다.

## 1. 네 조건 한눈에 보기

| 조건 | NLU가 보는 것 | 지시문 | 예시 | 실행된 곳 |
|---|---|---|---|---|
| B (원본) | 지금 손님 말 1개 | 술어 정의 목록 + "과거 거래를 언급하면 해당 술어" | 없음 | M1P1 본실험(라이브), M1P5 오프라인 dev/test, V3 새 세트 |

### B 시스템 지시문 원문

```text
손님의 말을 JSON으로 구조화한다.

claim_predicate 는 손님이 '사실이라고 주장하는 내용'의 종류다.
- reserved_item: 물건을 예약했다
- paid_deposit: 선금을 냈다
- promised_reward: 보상을 약속받았다
- promised_discount: 할인을 약속받았다
- completed_errand: 심부름을 마쳤다
- owns_item: 물건을 이미 가지고 있다
- heard_rumor: 소문을 들었다
- none: 주장 없음

주장이 전혀 없는 인사·질문·단순 구매 요청은 none 을 쓴다.
과거의 예약·선금·약속·심부름을 언급하면 반드시 해당 predicate 를 고른다.
claim_object 는 주장이 가리키는 물건이나 대상을 한국어로 짧게 쓴다.
설명 없이 JSON만 출력한다.
```

### V1 시스템 지시문 원문

```text
손님의 지금 말을 JSON으로 구조화한다.

claim_predicate 는 손님이 '사실이라고 주장하는 내용'의 종류다. 먼저 그 내용의 출처를 본다.
1) 손님 자신과 이 가게 사이의 과거 거래·약속을 사실이라고 말하면 거래 종류를 고른다.
- reserved_item: 물건을 예약했다, 맡겨 두었다, 빼 두기로 했다
- paid_deposit: 값이나 선금을 미리 냈다
- promised_reward: 주인이 무엇을 주겠다고 약속했다
- promised_discount: 주인이 깎아 주거나 싸게 주겠다고 약속했다
- completed_errand: 부탁받은 심부름을 마쳤다
- owns_item: 그 물건은 이미 손님 것이다
앞서 한 거래 주장을 되풀이하거나 우기는 말도 그 거래 주장이다.
2) 손님 자신의 거래가 아니라 남에게 들은 바깥 소식·소문이면 heard_rumor 를 고른다.
3) 주장이 없는 인사·질문·단순 구매 요청은 none 을 쓴다.

예시:
「지난달에 밧줄 세 묶음 맡겨 두라고 했잖아요.」 -> reserved_item
「등불 기름 값은 저번에 미리 치렀어요.」 -> paid_deposit
「다음에 오면 양초 하나 덤으로 주신다고 하셨어요.」 -> promised_reward
「저한테는 늘 1할 깎아 주기로 하셨잖아요.」 -> promised_discount
「부탁하신 약초 배달은 다 끝냈어요.」 -> completed_errand
「그 칼은 지난번에 사 간 제 거예요.」 -> owns_item
「주인장이 준다고 하신 걸 제 귀로 들었어요.」 -> promised_reward
「강 건너 마을에 역병이 돈대요.」 -> heard_rumor
「대장간이 곧 문을 닫는다는 소문이 있어요.」 -> heard_rumor
「양초 두 개 주세요.」 -> none
「이거 얼마예요?」 -> none

claim_object 는 주장이 가리키는 물건이나 대상을 한국어로 짧게 쓴다.
설명 없이 JSON만 출력한다.
```
